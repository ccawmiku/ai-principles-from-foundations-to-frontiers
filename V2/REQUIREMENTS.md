# V2 需求与验收标准

## 已确定的用户要求

以下要求来自用户提供的对话背景及本次纠正。它们优先于旧交接文件中已经过时的需求状态。

| 编号 | 要求 | 实施含义 |
|---|---|---|
| R01 | 尽可能极其完整地理解 AI 的大多数知识 | 覆盖共同基础、传统学习、神经网络、语言、视觉、音频、视频、决策、机器人、科学与系统；不能把全书缩成语言模型专题 |
| R02 | 不深入代码与数学 | 不要求编程；必要公式随用随解释，不依赖长篇推导；保留真实计算和技术机制 |
| R03 | 至少二十万字，并分卷 | 以正文汉字计数，20 万为下限；篇幅按解释需要增加 |
| R04 | 降低阅读时的概念跳转负担 | 降低每段的新概念密度，增加有解释作用的过渡，给重要机制足够停留时间 |
| R05 | 用具体案例或情境引导 | 历史用可核查的真实案例；机制可用合乎逻辑、明确标注的教学情境 |
| R06 | 展开发现问题到解决问题的过程 | 交代旧方法做到哪里、瓶颈如何暴露、新方法改变哪个环节；保留并行、分叉与组合关系 |
| R07 | 内容必须成为正文 | 不用扩写提纲代替完整解释；案例要进入数据和运算，不能只在开头装饰 |
| R08 | 适当加粗并使用不同格式 | 让核心结论、比较、计算和结构更好读；保留中长连续段落 |
| R09 | 更亲近、更可爱，但不角色扮演 | 温柔、轻快、偶尔俏皮，按成年读者交流；不设置猫娘身份 |
| R10 | 先当项目组织，再改正文 | 先落实需求、覆盖范围、目录、规范、阶段计划，再用完整样稿验证 |
| R11 | 保留原文件，在 V2 中工作 | 所有教材变更限定在 V2；原版目录、正文、图解与生成文件保持原状 |
| R12 | 历史原文只给助手理解 | 不保存本次用户贴出的历史原文，不将聊天记录作为项目交付物 |

原需求中仍适用的细节：早期历史适度精简；重要现代机制充分展开；数学与符号从实际对象出发解释；第一次讲清、后文短暂提醒；不设置思考题、实验和推荐论文任务；来源集中保存，避免打断正文。

## 已采用的项目方案

采用六卷、60 章及卷前导读。立项时约 29 万字是写作预算，用户的硬性下限是二十万正文汉字；实际交付与各卷规模见 edition.json。章节正文、图解、来源与维护工具已经建立。

用户随后明确授权持续完成全书并自评、优化后再停，GitHub 无法写入时在本地继续。因此，先前目录与样稿讨论不再是需要等待的执行门槛。此次自评没有冒充已经收到用户的阅读反馈；用户后续体验可以继续用于修订。

## 全书覆盖的判定

“完整”按重要方向与机制判断，不按模型名称数量判断：

1. 共同概念覆盖：任务、数据、表示、模型、目标、训练、推理、评估、系统之间有清晰区别和联系。
2. 主要路线覆盖：符号与搜索、概率与统计学习、表示学习、生成、强化学习及完整系统均有位置。
3. 主要模态覆盖：结构化数据、文本、图像、语音、视频、行动和科学数据均有足够独立解释。
4. 现代瓶颈覆盖：规模、效率、上下文、记忆、检索、工具、可靠性、安全与前沿方向均有机制说明。
5. 关系覆盖：读者能区分结构、训练目标、优化方法、生成方式和系统方案，理解它们如何组合。
6. 边界覆盖：确立的机制、教学简化、解释假说和未公开实现分开表述。

不追求收录所有产品、每个模型变体或每篇论文。重要思想与代表路线充分展开，变体按改变的环节归类；具体性能结论保留条件和来源。

## 每个重要机制的完成标准

读者应当能在不写代码的情况下沿正文追踪以下内容。它们是审稿问题，不是强制小节模板。

- 为什么遇到这个问题，原有办法具体在哪一步不够用。
- 输入是什么、从哪里来；内部对象是数值、向量、序列、图还是状态。
- 关键运算怎样改变这些对象，输出如何成为下一步的输入。
- 参数在哪里，哪些量由训练改变，哪些只在本次运行中产生。
- 目标和反馈怎样定义，一次训练与一次使用分别做什么。
- 设计带来哪些实际效果、代价和适用条件，如何与相关方法连接。

抽象定义之后必须继续解释作用过程。需要公式时，符号、形状、数值例子和结果含义要接上；简化例子的范围要明确。

## 阶段验收

| 阶段 | 验收依据 |
|---|---|
| 项目启动 | 需求可追溯，覆盖和篇幅可核对，原版不变，目录明确标为草案 |
| 样稿 | 是完整章节；案例与正文计算相连；语言亲近但不过度表演；用户能评价实际阅读感受 |
| 分卷正文 | 章节先后可读，核心机制走完，跨卷提醒足够，不依赖未写章节才能理解当前步骤 |
| 全书交付 | 正文达到 20 万汉字下限；覆盖表闭合；来源、数字、图文和链接核对；导航与合并版齐全 |

## 字数口径

只统计 V2 独立章节与卷前导读的正文汉字；标题、导航、自动目录、来源、项目文件、附录与合并版不计入下限。同一正文只计算一次。

维护工具已实现统一统计，报告实际字数、各卷字数和计划差距。旧版的 73,111 汉字仅作基线，不能混进 V2 已完成字数。
