当我们在上一卷结束语言模型的探讨时，送入模型的一切信息本质上都是一维离散的文本符号（Token）。模型计算的逻辑建立在词与词的前后顺序、上下文共现和自回归概率之上。但现实世界的智能远不止文本。想象一位设备运维工程师站在嘈杂的车间里，用手机拍下一张工业水泵的照片，上传给系统并询问：“水泵接线盒上的右侧螺栓有没有松动？电缆保护套有没有破损？”

这时候，系统面对的不再是一串干净的汉字，而是一堆原始的光学信号。我们不能简单地把图片当作“另一种格式的文本”敷衍了事。图像拥有连续的空间拓扑、颜色通道、光影渐变以及多样的拍摄视角。计算机究竟怎样把这张由数百万个光敏传感器读数构成的数字矩阵，一步步转化成可以计算、理解和推理的视觉特征？这一章我们就从最基础的像素阵列切入，拆解现代视觉模型理解空间结构的核心秘密。

<a id="section-01"></a>
## 从光子到张量：像素矩阵究竟存了什么

在数字相机的传感器上，镜头捕捉到的光线被滤色镜分解，光子撞击光电二极管产生微弱的电荷，经过模数转换（ADC）后，最终变成存储在内存中的一个多维数字矩阵。

对于最常见的彩色照片（RGB 图像），每个空间位置都记录了红（Red）、绿（Green）、蓝（Blue）三种原色的强度。如果一张图片的分辨率是 1920×1080，就意味着在水平方向有 1920 个采样点，垂直方向有 1080 个采样点。在计算机内存中，这通常表现为一个形状为高（H）× 宽（W）× 通道数（C）的三维数组（或通道优先的 C×H×W 格式）。

```
图像矩阵的物理排布：
高度 H (行) × 宽度 W (列) × 通道数 C (3 个通道：R, G, B)
每个像素点 (h, w) 对应一个三元组向量 [r, g, b]
```

在常见的 8 位无符号整数（uint8）编码下，每个通道的数值落在 0 到 255 之间，数值越大代表该颜色分量越强。当这个数组送入深度学习模型前，工程师通常会做一步归一化预处理：先除以 255 缩放到 [0, 1] 区间，再根据标准数据集（如 ImageNet）的均值与方差做标准化，使像素值分布在 0 均值、单位方差的浮点数区间内。

但必须看清的是，**像素值本身并不是物体的语义属性**。一个像素点的数值为 [220, 45, 45]，仅仅代表传感器在那个极小区域内采集到了较强的红光。这究竟是红色的急停按钮、设备外壳的反光、报警指示灯，还是维修工人的红色工装？单看孤立的像素甚至几十个像素，我们根本无法得出结论。更重要的是，现实世界中的输入远不止三通道彩色照片：
- **热成像图**：单通道记录红外辐射能量，数值代表真实的表面温度场；
- **深度图（Depth Map）**：每个像素值直接对应物理距离（例如毫米或米）；
- **遥感多光谱图**：可能包含近红外、短波红外等十几个频段。

把它们统称为“图像”，并不意味着可以用完全相同的前处理方式和模型权重草率对待。视觉计算的第一原则，就是明确底层数组的具体物理意义。

<a id="section-02"></a>
## 为什么原始像素阵列离“理解物体”十万八千里

人类在看一张设备照片时，大脑会在毫秒级时间内自动完成边缘提取、表面重构、阴影剥离以及物体识别——你一眼就能认出中间有一颗银白色的六角螺栓。但对于纯粹依赖矩阵运算的算法来说，原始像素阵列充满了欺骗性与脆弱性，这在计算机视觉中被称为**语义鸿沟（Semantic Gap）**。

造成这种鸿沟的核心原因有三个：

| 扰动类型 | 像素矩阵的变化 | 人类感知的语义 | 传统算法的困境 |
| :--- | :--- | :--- | :--- |
| **平移与轻微移动** | 物体右移几个像素，整个矩阵中对应位置的数值全部翻天覆地 | 依然是同一台设备、同一颗螺栓 | 如果使用全连接网络，权重无法跨位置复用，特征直接错位 |
| **光照与阴影变化** | 阳光被云层遮挡或开启补光灯，所有像素数值整体偏移数十甚至上百 | 物体材质与形状完全未变 | 像素绝对值大幅变动，直接欧氏距离度量彻底失效 |
| **视角与遮挡旋转** | 俯视拍摄变为斜上方 45 度侧拍，轮廓和投影长宽比剧烈畸变 | 空间几何结构恒定 | 像素之间的空间拓扑彻底洗牌 |

如果我们直接拿两个展平的像素向量去计算点积或欧氏距离，往往会发现：同一张设备照片在开灯和关灯状态下的距离，远远大于它与一张完全无关的灰色墙面照片的距离！

要跨越这条鸿沟，计算机必须学会提取**对光照、平移、尺度变换具有鲁棒性的抽象表示**。模型不能停留在孤立数值的层面，而必须建立对局部纹理、几何边缘、部件组合直至全局语义的逐级抽象能力。而要实现这种抽象，学术界和工业界先后走出了两条截然不同的主流架构道路。

<a id="section-03"></a>
## 卷积与自注意力：视觉特征提取的两种流派

在过去的十几年中，深度视觉模型的发展主要由两大流派推动：基于局部归纳偏置的**卷积神经网络（CNN）**，以及基于全局内容路由的**视觉注意力网络（Vision Transformer, ViT）**。

### 1. 卷积网络：把物理世界的局部性刻进骨子里
我们在第二卷学习卷积时已经明白，卷积操作具有两大强烈的“归纳偏置”（Inductive Bias）：
- **局部连接（Locality）**：物理世界中的像素只与邻近像素具有强空间关联（比如一条螺栓边缘的像素彼此相邻，但与三米外的天花板像素毫无直接几何关系）。卷积核每次只在 3×3 或 5×5 的小窗口内计算。
- **权值共享与平移等变性（Translation Equivariance）**：无论螺栓出现在画面的左上角还是右下角，检测边缘的滤波法则完全一致。同一个卷积核在整张特征图上滑动，天生保证了物体移动时特征也会随之对应平移。

这种设计使得 CNN 在参数量非常精简的情况下，具有极高的数据利用效率，极度适合小样本或算力受限的边缘端场景。

### 2. 自注意力网络：打破局部枷锁的动态路由
然而，卷积也有天然的局限性：它的感受野（Receptive Field）是逐层线性扩大的。如果想让模型感知相隔很远的两个部件之间的关系（例如电缆的起点与水泵电机的连通性），必须堆叠极深的网络层数，且远距离信息的传递容易在多层池化和下采样中被稀释。

Transformer 的自注意力机制（Self-Attention）则完全不同。它允许画面中的任意两个位置之间直接计算关联度权重：
- 每个视觉单元（Patch Token）都可以根据自身内容，动态决定向全图的哪一个单元“借力”；
- 它的归纳偏置极弱，没有硬编码的局部滑动窗口，空间位置全靠位置编码显式告知；
- 当训练数据极其庞大时，弱归纳偏置反而展现出巨大的上限——模型能够自由学习远距离的复杂几何与上下文依赖。

现代工程实践早已不是非此即彼的宗教式站队。像 ConvNeXt 吸收了 Transformer 的宏观设计重塑现代纯卷积，而 Swin Transformer 则在 Transformer 中引入局部滑动窗口降低计算复杂度。理解两者的底层差异，是选择和优化模型架构的立足点。

<a id="section-04"></a>
## 把图片切成方块：ViT 如何把二维空间变成序列

自然语言模型之所以能用 Transformer 一统天下，是因为文本天生就是由一个个离散词素构成的序列。图片怎么也能当成序列送进 Transformer 呢？这就是 Vision Transformer（ViT）开创性的核心思想：**把图片当成文章，把切开的图像块当成单词（Visual Token）**。

![像素到图像块，再到视觉表示](../../assets/vision.png)

我们通过一个经典的尺寸例子来把这条流水线彻底盘清楚：

假设输入的设备照片经过裁切缩放后，分辨率为标准的 224×224 像素，色彩通道数为 3（RGB）。ViT 的处理流程分为四步：

1. **空间分块（Patch Partition）**：
   选择一个固定的块大小（Patch Size），最经典的是 16×16 像素。
   在水平方向上可以切出 $224 / 16 = 14$ 个切片；
   在垂直方向上同样可以切出 $224 / 16 = 14$ 个切片。
   整张图被整整齐齐地切成了 $14 \times 14 = 196$ 个互不重叠的图像方块（Patch）。

2. **展平与线性投影（Patch Projection）**：
   每个 16×16 的彩色小方块包含的原始数值个数为：
   $$16 \times 16 \times 3 = 768 \text{ 个数值}$$
   我们将这 768 个数值展平成一个 768 维的原始向量，然后通过一个可学习的线性映射层（全连接层或一个卷积核大小为 16×16、步长为 16 的卷积层），把它投影到模型的主干隐空间维度 $d$（例如 ViT-Base 中 $d = 768$）。至此，原本的二维空间图像变成了长度为 196、维度为 $d$ 的序列矩阵：$[196, d]$。

3. **注入空间位置信息（Positional Embedding）**：
   自注意力机制本身是对位置完全钝感的（Permutation Invariant）。如果不做任何处理，把左上角的块和右下角的块随意对调，注意力的计算结果完全相同！这在几何视觉中是致命的。
   因此，ViT 为这 196 个位置分别配上一个 $d$ 维的可学习位置向量（也可以使用二维正弦余弦编码），将其逐元素加到图像块向量中：
   $$\text{Token}_i = \text{PatchEmbedding}_i + \text{PositionEmbedding}_i$$
   这样，每个 Token 不仅包含了自己方块内的纹理细节，还记住了自己在整张图中的坐标坐标。

4. **分类标记与全局汇聚（[CLS] Token 与 Pooling）**：
   如果任务是整图分类，ViT 往往会在 196 个视觉 Token 的最前面拼入一个专门的可学习分类标记 `[CLS]`（维度也是 $d$），形成总长度为 $196 + 1 = 197$ 的序列。经过多层 Transformer 块的自注意力交互后，提取 `[CLS]` 位置对应的最终向量，送入分类头输出预测概率。在很多后续模型中，也可以直接对 196 个 Token 的输出取全局平均池化（Global Average Pooling）。

通过这一套优雅的转换，复杂的二维光学信号成功嫁接到了现代大语言模型最通用的序列处理引擎之上。

<a id="section-05"></a>
## 分辨率的权衡：多看一眼的成本有多高

在工业质检、医疗影像或自动驾驶中，工程师最直观的冲动往往是：**把图片分辨率拉得更高一些**。

这很符合直觉：在 224×224 分辨率下，水泵法兰盘上一道 0.2 毫米的细小裂纹可能连一个像素都占不满，早就在插值下采样中被抹平了；如果提高到 896×896 甚至 1792×1792，裂纹的边缘和纹理就会历历在目。但为什么模型不能无限度地提高输入分辨率？

这里的核心制约在于**注意力机制随空间面积爆炸的计算复杂度**：

| 分辨率 | 图像边长倍数 | 16×16 块数量 (序列长度 $N$) | 全注意力计算对数 ($N^2$) | 显存与计算开销对比 |
| :--- | :--- | :--- | :--- | :--- |
| **224 × 224** | 1× 基准 | $14 \times 14 = 196$ | $196^2 \approx 3.84 \times 10^4$ | 基准成本（轻量） |
| **448 × 448** | 2× | $28 \times 28 = 784$ | $784^2 \approx 6.15 \times 10^5$ | 约 16 倍注意力计算量 |
| **896 × 896** | 4× | $56 \times 56 = 3136$ | $3136^2 \approx 9.83 \times 10^6$ | 约 256 倍注意力计算量 |

你看，边长仅仅翻了 4 倍，图像块数量翻了 16 倍，而全图自注意力的位置对交互计算量直接飙升了 **256 倍**！在实际部署中，高分辨率不仅会让 GPU 显存迅速告罄，还会导致推理延迟无法满足产线实时节拍。

为了兼顾微观细节与计算预算，工业界演化出了几种典型的架构妥协：
1. **多级分辨率与滑动窗口（如 Swin Transformer）**：不在全图做跨块注意力，而是把自注意力限制在 7×7 的局部小窗口内，再通过交替移动窗口（Shifted Windows）传递全局信息，把计算复杂度从 $O(N^2)$ 压制回与像素面积成正比的 $O(N)$。
2. **动态多裁切策略（AnyRes / Patch-and-Merge）**：对于超高分辨率图，先生成一张缩小的全局缩略图把握宏观语义，再把关键区域切成若干局部高分辨率方块独立编码，最后把多块特征拼接送入多模态大模型（我们在第 40 章会专门拆解这种做法）。

<a id="section-06"></a>
## 全局语义与密集空间：下游任务需要不同粒度的表示

当一幅图像在模型内部流转时，不同网络层输出的特征并非铁板一块。如何提取和组织这些特征，完全取决于你的实际工程目标。

```
图像输入
  ↓
浅层特征图 (分辨率极高，关注点线纹理、颜色边缘、几何细部)
  ↓
中层特征图 (分辨率中等，聚合出零件局部、螺母轮廓、电缆接头)
  ↓
深层特征图 (分辨率较低但感受野极大，理解“水泵机体”、“工作台环境”等抽象概念)
  ↓
全局压缩向量 (1×d 向量，只保留“图中有没有水泵”的全局判定，丢失空间位置细节)
```

如果你的任务仅仅是**整图分类**（例如判断图片是“水泵设备”还是“发电机组”），你只需要提取最后一层特征，通过池化或 `[CLS]` 获得一个紧凑的全局向量。这个向量舍弃了“螺栓具体在画面哪一行哪一列”的细节，换来了高度抽象的类别判别力。

但如果任务是**缺陷定位（检测）**或**像素涂色（分割）**，只拿最后一个全局向量就彻底抓瞎了——因为空间坐标早就在全图压缩中丢失了。此时，算法必须提取中间层的**空间特征图（Feature Map）**，保留每一个 Token 对应的网格位置。下一章我们将看到，目标检测算法是如何利用多尺度特征图，在同一张图里既抓住占据半张画面的整机机壳，又精确定位仅占几个像素的松动螺钉的。

<a id="section-07"></a>
## 走向真实世界：拍摄条件与视觉先验的偏差

在纸面上讨论算法时，我们假设输入的是分布完美的标准图像。但在真实的工业现场或手机端，相机的采集环境充满了噪声与欺骗：

1. **光照与反光陷阱**：强光照射在不锈钢表面产生的镜面高光，可能被模型误判为一道裂缝；车间背光处的电缆由于阴影漆黑一片，细节彻底淹没在暗区噪声中。
2. **背景捷径（Shortcut Learning）**：这是视觉模型在实际部署中最容易踩的雷。如果训练集中所有“有缺陷的水泵”都是在专门的维修间台架上拍的，而“正常的水泵”都是在现场车间装配线上拍的，模型完全不需要学会看螺栓松动，它只需要偷偷学会检测“背景里有没有维修台的黄黑警示线条”就能取得 99% 的训练准确率！一旦把它装到车间现场，面对正常机器就会大规模误报。
3. **传感器与视角泛化**：用单反相机训练的模型，放到低成本广角工业镜头或鱼眼镜头前，由于镜头畸变和动态范围的差异，特征分布可能发生剧烈漂移。

纯粹的矩阵运算能够为我们提供强大的特征提取机制，但它不会凭空补充物理世界的因果关系。要让视觉模型真正落地，我们必须理解这些可计算的结构究竟在什么假设下有效，并在数据采集中严格隔离环境捷径。

在这一章里，我们打通了从物理光子到像素阵列、再到 ViT 视觉序列与特征表示的全流程。接下来，我们将正式进入具体视觉任务的战场：当模型拿到这些空间特征后，它是如何找出图中的每一个物体、画出精准的边界框、并细化到每一个像素的？下一章，我们聚焦目标检测与图像分割。
